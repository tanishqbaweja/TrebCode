Fixed the RELEASE-only crash by editing only `/app/user.cpp`.

**Root cause:** The in-house libstdc++ (`/build/patches/locale_init.cc.patch` + `locale_classes.tcc.patch`) lazily allocates 5 MSVC-style `_Fac_node` facet nodes on the first `__try_use_facet`/`use_facet` after static init, and frees them in a static destructor after `main()` exits. In RELEASE (`NDEBUG`) the nodes and their 256-byte payloads use `new`/`delete` (routed through `main.cpp`'s global `operator new/delete` → bump-allocator custom heap while active); in DEBUG they use `malloc`/`free`. If first registered while the custom heap is active (the `std::cout` calls in `Application::init/run`), the nodes live in the heap buffer, which `shutdown()` frees/poisons — the exit-time cleanup then `delete[]`s/`operator delete`s dangling pointers → segfault after "completed successfully". Compiling `/app` against system headers means header-inline `use_facet` in user code does not trigger registration; only prebuilt-library internals do.

**Fix (`user.cpp::user_init`, runs before the custom heap is created):** directly call the library-internal `std::_Facet_Register_impl()` (declared in the custom headers, defined in `locale_init.cc`) plus a public `has_facet`/`use_facet` warmup. This forces the one-time registration while `g_custom_heap == nullptr` (malloc-backed), so later facet uses under the heap allocate nothing and exit-time cleanup frees valid pointers. No outliving allocations, so no leaks.

**Verification:**
- Rebuilt with the exact task commands (release `-O2 -DNDEBUG` + custom-release lib, debug `-g -O0` + custom-debug lib): both build OK.
- Before fix: debug exit 0, release segfault (139) after final output. After fix: `release exit 0` ×3 plus with `LD_LIBRARY_PATH`, `debug exit 0` — output (π ≈ 3.142428) unchanged.
- Valgrind `--leak-check=full --show-leak-kinds=all --error-exitcode=42`: both binaries exit 0, `ERROR SUMMARY: 0 errors`, `definitely/indirectly/possibly lost: 0`.
