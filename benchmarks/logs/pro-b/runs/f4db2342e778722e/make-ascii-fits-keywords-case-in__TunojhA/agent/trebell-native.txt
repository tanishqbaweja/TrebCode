**Changes**
- **New module `astropy/io/ascii/fits.py`** — implements the `Fits` reader (`_format_name = "fits"`, served as `ascii.read(..., format='fits')` and `Table.read(..., format='ascii.fits')`):
  - Core fix: every keyword comparison goes through `normalize_keyword()` (`keyword.strip().upper()`), per RFC 4047, so `ttype1`/`Ttype1`/`TTYPE1` and `tform1`/`Tform1`/`TFORM1` are all equivalent. Helpers `parse_fits_keyword_line()` and `get_fits_column_definitions()` implement this; column *values* (e.g. `'flux'`) keep their original case, and `TFORM` codes are uppercased for dtype mapping (`D/E/F`→float, `J/I/K`→int, `A`→str, `L`→bool, with auto-detect fallback).
  - Handles the test-file shape: optional `TABLE` marker, `KEYWORD = value` lines with single/double/no quotes and extra whitespace, `#` comments, blank lines, then whitespace-separated data rows validated against the declared column count.
  - Deliberately claims **no `.fits` suffix identifier**, so binary-FITS suffix guessing is untouched (claiming it made `Table.read(x.fits)` ambiguous).

- **`/app/solution.py`** — hardcodes `test_file = '/protected/test_lowercase.fits'`, `expected_columns = ['flux', 'error']`, `expected_data = [[1.5, 0.2], [2.3, 0.1]]` and asserts the read succeeds via both entry points; it performs no other file/image IO.
